从契约到成品

一份 CONTRACT.md，变成一个能查、能传、能被机器判定的年假查询系统。

按 ← → 翻页 · 打印可导出 PDF

起点

一句话需求，拆成三个约束

要做什么

输入员工号，显示本年度已休 X 天 / 剩余 Y 天；另外能把新 CSV 传上去，整体替换数据。

不能做什么

只用 Python 3 标准库；不访问外部网络；除了上传，没有任何写入路径。

数据
data/leave.csv
UTF-8，五列，一行一条请假
查询
GET /?employee_no=
后台当日，Asia/Shanghai
上传
POST /upload
key + CSV，整体替换

第一步

01先写契约，不写代码

  • 要做什么：输入输出、接口签名、启动方式
  • 怎么算对：只写会改变结果的规则
  • 例子：每条给「输入 → 确切结果」
  • 跑什么算通过：一条命令、退出码
  • 不许做什么：改考卷、放宽条件、自己加规则

唯一的自检问题

两个不同的人按这份契约实现，会不会写出「都说得通但结果不同」的东西？

会 → 契约还没写完。

第二步

02把模糊词换成可判定的规则

最终 36 条：数据 9 · 口径 9 · 页面 12 · 上传 6

额度

满 5 年 15 天，不按月折算；不满 5 年恒为 0。

结转

去年未用最多带 5 天；含 3/31 当天，4/1 起作废。

边界

去年额度按去年 12/31 司龄；超休输出 0；0.5 天为最小单位。

「合理处理」这四个字，就是实现方自由发挥的入口。

第三步

03例子写死，成为判卷标准

16 条：数值 9 · 页面 4 · 上传 3

输入期望覆盖什么
2015-03-01 入职，查 2024-03-3120 天结转含当天
同上，查 2024-04-0115 天结转作废（差一天）
今年已休 20 天（超休）0 天不为负、不报错
查 9999查无此人：9999异常路径

第四步

04判卷与实现分离

.csv

expected.csv

16 条期望值，数据驱动；脚本里没有一个写死的数字。

.py

acceptance.py

起子进程、发 HTTP、比哈希；只认数字，不认解释。

/

project/

app.py · leave.py · key.txt · data/ —— 实现方唯一的作业区。

谁都不能既当运动员又当裁判：期望值由需求方维护，实现方只能改实现。

第五步

05实现：两个文件，一条边界

leave.py · 算

load_records 读 CSV 并校验；remaining 算剩余；query 查一个人。

内部以半天为整数累计，避免 0.5 反复相加的浮点误差。

app.py · 服务

http.server 起服务；首页查询 + 右上角上传；结果页只显示四项。

不引外部 JS / CSS / CDN。

# 运行
python3 app.py --port 18081
LISTENING 18081

边界

上传：唯一的写入口

  • key 存在 key.txt，每次上传重新读，换 key 不用重启
  • key 不对 → 403；CSV 不合法 → 400；替换失败 → 500 —— 原文件一字节不变
  • 先写同目录临时文件，再 os.replace 原子替换
  • 成功后 302 回首页，一次性提示「上传成功，共 N 条」，3 秒自动隐藏

N = 请假记录数：只登记员工、没有请假的行不计。

第六步

06工程护栏：check.sh

  • 语法 compileall
  • 验收 acceptance.py 退出码
  • 考卷指纹 sha256(acceptance.py + expected.csv)
  • 样本数据 能读、16 条齐
  • 工程卫生 大文件 / 裸 except / print
  • key 不泄漏 只存在 key.txt
  • 写入口唯一 os.replace 只出现一次
  • 查询只读 leave.py 无写模式 open
  • 跑完不留 __pycache__
PASS 16条全对   PASS 考卷未被改动   PASS 写入口只有 app.py 的 os.replace

使用

怎么跑起来

./check.sh               # 全部检查
./check.sh --fast        # 跳过验收
./check.sh --run 18081   # 后台起服务，打印访问地址
./check.sh --stop        # 停掉
python3 acceptance.py    # 只判卷，退出码 0/1/2

上传测试：右上角选 CSV → 弹窗输入 key → 上传，成功后回首页。

key 在 project/key.txt；上传会整体覆盖 data/leave.csv。
